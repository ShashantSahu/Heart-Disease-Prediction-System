# CardioScore Pro - Heart Disease Risk Prediction System

A machine-learning web application that estimates the probability of heart disease from
clinical measurements, trained on the labelled **UCI Heart Disease (Cleveland)** dataset.

> **Disclaimer:** CardioScore Pro is an educational project. Its output is a statistical risk
> estimate, **not a medical diagnosis**. It must not replace advice from a qualified doctor.

---

## 1. Core requirements (college project)

| # | Requirement | Where it is implemented |
|---|---|---|
| 1 | **Dataset handling** - load data, check missing values, clean, preprocess | `train_model.py`: `load_dataset`, `validate_and_clean`, `build_preprocessor` |
| 2 | **Input features** - age, sex, chest-pain type, blood pressure, cholesterol, blood sugar, ECG, max heart rate, exercise-related features and the other prescribed attributes (13 in total) | `FEATURES` list in `train_model.py` (also drives the form) |
| 3 | **ML prediction** - train on labelled outcomes and estimate heart-disease risk | `train_model.py`: `train_all`, `predict_risk` |
| 4 | **Model evaluation** - accuracy, precision, recall, F1-score, confusion matrix | `train_model.py` (+ ROC-AUC); shown on the *Model Performance* page |
| 5 | **Prediction interface** - enter details, see the result, understand it | `app.py`: *New Assessment* page |

## 2. Extra features (added on top of the core)

## 4. Setup and run

Python 3.9 - 3.12 is recommended.

```bash
# 1. open a terminal in the project folder
cd CardioScore_Pro

# 2. (recommended) create a virtual environment
python -m venv .venv
# Windows:        .venv\Scripts\activate
# macOS / Linux:  source .venv/bin/activate

# 3. install dependencies
pip install -r requirements.txt

# 4. dataset: save UCI "processed.cleveland.data" in data/  (see data/README.md)
#    or stay online and step 5 will try to download it

# 5. train, validate and save the models
python train_model.py

# 6. run the tests (optional but recommended)
python -m unittest discover -s tests -v

# 7. start the app
streamlit run app.py
```

If you start the app before training, it shows a clear message telling you to run
`python train_model.py`.

### What `python train_model.py` produces

* `models/*.joblib` - one fitted pipeline per model, and `models/metadata.json` (all metrics,
  confusion matrices, ROC points, importances, dataset report)
* `reports/model_comparison.csv` and `reports/training_report.md` - ready to copy into your
  college report (real numbers from your run)

If you upgrade scikit-learn later, run `python train_model.py` again so the saved models match.

## 5. Methodology

1. **Load and validate**: 13 features + outcome. Codes must match the original UCI coding.
2. **Clean**: unlabeled rows and duplicates removed, impossible values set to missing,
   missing values reported (Cleveland has 6: 4 in `ca`, 2 in `thal`).
3. **Preprocess (inside a scikit-learn Pipeline)**: median imputation + standardisation for
   numeric features; most-frequent imputation + one-hot encoding for categorical features.
   Because this is inside the pipeline, it is fitted on training data only (and re-fitted in each
   cross-validation fold) - **no train/test leakage**.
4. **Split**: stratified 80/20 train/test. The test set is used once, for final metrics.
5. **Validate**: 5-fold stratified cross-validation on the train part for every model.
6. **Select**: highest mean validation ROC-AUC (F1 breaks ties).
7. **Evaluate**: accuracy, precision, recall, F1, ROC-AUC, confusion matrix on the test set.
   Training accuracy is also shown to expose overfitting.
8. **Explain**: permutation importance (global) and what-if influence per prediction (local).

Risk bands shown to the user: LOW below 33%, MODERATE 33-66%, HIGH above 66%. These are display
thresholds, not clinical cut-offs.

## 6. Privacy and security notes

* Only salted PBKDF2-HMAC-SHA256 hashes are stored (600,000 iterations, random salt per user).
* All database queries are parameterised, and every history query is filtered by the logged-in
  user's id, so users cannot see, export or delete each other's assessments (covered by tests).
* This is a **local, single-machine** app. It has no password reset, no login rate-limiting and
  the login lasts for the browser session only (a page refresh logs you out). For a real
  deployment you would add HTTPS, rate limiting, e-mail verification and a server database.
* `data/cardioscore.db` holds health inputs. It is git-ignored; do not share it.

## 7. Limitations

* One small, old dataset (303 patients, one hospital, donated 1988, mostly male). It may not
  generalise to other populations.
* The outcome is "any disease vs none"; severity is not predicted.
* About 46% of patients in the dataset have the disease, much more than in the general
  population, so the probability is relative to this dataset, not a true real-world risk.
* The test set is small (about 60 patients), so metrics are uncertain; see the +/- values.
* Explanations show what the model relies on, not medical causes.
* Smoking, family history, diabetes status, BMI, medication and ethnicity are not in the data.
